Indexed recurrent-state GDN candidate — evaluated, NOT SHIPPING

Release verdict
---------------
DROP from tonight's release by orchestrator decision. The measured 1.3%
generation gain does not justify introducing a cache-lifecycle change
without full lifecycle qualification. This is not a performance regression.
The candidate remains only as rejected-state-gather.patch in this evidence
directory and the local experiment tree. It is not in the Buildroot package
patch directory, is not default-on and was not installed on the device.
The shipping recommendation is unchanged: 0001 followed by rows-only 0002.

Design
------
Reuse the existing indexed-state GDN K=1 operator only for CPU, one token,
one sequence, one live recurrent row, no snapshots/replay, fused AR, F32
contiguous state. Preserve the runtime source-row index, state zeroing and
normal final-state writeback. Do not assume the source is row zero or the
destination head. Other configurations retain the gathered path.
No arithmetic kernel or cache serialization format changes.

Correctness and limitations
---------------------------
GCC 12.2 and Buildroot GCC 13.4 each passed 72 complete output/state memcmp
cases under qemu-aarch64 -cpu cortex-a35, -O2 -march=armv8-a. Cases cover
head dimensions 16/64/128, 1/4 threads, source rows 0/1/2, raw gates on/off
and zero/random cache states. See test-state-rows.cpp and correctness.txt.
Two independent source reviews found no introduced defect in either the
rows kernel or this guarded graph selection.

These operator checks do not exercise actual cache writeback, graph reset
ordering, reused graphs following sequence operations or save/restore
continuation. Source review supports those invariants, but is not an
end-to-end bit-exact lifecycle test. No additional device lifecycle test
was run after the device was released to the orchestrator's queue.

Profile confirmation, not a speedup estimate
-------------------------------------------
The callback profile confirms the branch activates. Median summed decode
GET_ROWS time changes from 25.428 ms to 1.934 ms. The node count remains
40: the 18 large state gathers become zero-row tail metadata rather than
disappearing from the graph. For example, the first recurrent gather
changes from shape [262144,1] to [262144,0]. Callback dispatch/synchronizing
inflates small operations; use the AB/BA table, not this timing difference,
for the measured end-to-end effect.

Other measurement
-----------------
The OpenMP disposable-pool probe measured 100000 new/free pairs in
0.202524583 seconds: 2.025246 microseconds per pair. This directly rules
out a 10-50 ms pool-allocation explanation for the historical app gap on
this build. It does not measure all OpenMP region or graph-planning costs.
